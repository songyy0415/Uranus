## 2. 已验证的 MC 26.3 API 变化（本项目受影响面）

编译基线：`./gradlew :common:compileJava` 在 26.3 下仅 29 个错误，集中在渲染层。

### 2.1 `com.mojang.blaze3d` GPU 类迁移到 `com.mojang.renderpearl.api`（破坏性）

26.3 将原 blaze3d GPU 抽象整体迁到 RenderPearl API：

| 26.2 | 26.3 |
|---|---|
| `com.mojang.blaze3d.GpuFormat` | `com.mojang.renderpearl.api.GpuFormat` |
| `com.mojang.blaze3d.systems.GpuDevice` | `com.mojang.renderpearl.api.device.GpuDevice` |
| `com.mojang.blaze3d.textures.GpuTexture` | `com.mojang.renderpearl.api.textures.GpuTexture` |
| `com.mojang.blaze3d.textures.AddressMode` | `com.mojang.renderpearl.api.textures.AddressMode` |
| `com.mojang.blaze3d.textures.FilterMode` | `com.mojang.renderpearl.api.textures.FilterMode` |

类/方法签名本身不变（`RenderSystem.getDevice()` 返回新包 `GpuDevice`；
`device.createTexture(label, usage, format, w, h, depth, mips)`、
`SamplerCache.getSampler(u, v, min, mag, mipmaps)`、
`CommandEncoder.writeToTexture(GpuTexture, NativeImage)` 均在 26.3 存在）。
`AbstractTexture` 的 `texture / textureView / sampler` 字段仍在。
**结论：`SimpleTexture` 只改 import。**

### 2.2 `PoseStack.mulPose(Quaternionfc)` 删除（破坏性）

26.3 `PoseStack`（`com/mojang/blaze3d/vertex/PoseStack.java`）只剩：

- `mulPose(Matrix4fc)`
- `mulPose(Transformation)`
- 新增 `rotate(Quaternionfc)`、`rotate(Axis, float)`、`rotateDegrees(Axis, float)`、`rotateAround(...)`

26.2 代码 `poseStack.mulPose(Axis.ZP.rotation(angle))` 的等价写法是
`poseStack.rotate(Axis.ZP.rotation(angle))`（等价四元数旋转，语义不变）。
涉及：`BasicModelPart`、`AdvancedModelBox`、`IArmorRenderHelper`。

### 2.3 `OrderedSubmitNodeCollector.submitModel` 参数变更（破坏性）

- 26.2：`submitModel(model, state, poseStack, renderType, light, overlay, outlineColor, @Nullable CrumblingOverlay)`（8 参默认重载）
- 26.3：`submitModel(model, state, poseStack, renderType, light, overlay, outlineColor)`（7 参默认重载）；
  完整重载为 9 参 `(..., tintedColor, @Nullable UvMapping, outlineColor)`，不再有 `CrumblingOverlay` 参数。

**结论：本项目的 8 参调用删掉末尾 `null` 即可。**
涉及：`ArmorModelBase`、`IArmorRendererBase`、`IArmorRenderHelper`。

### 2.4 `RenderTypes.armorEntityGlint()` 删除（破坏性）

26.2：无参 `armorEntityGlint()`，内部使用 `GLINT` pipeline +
`ENCHANTED_GLINT_ARMOR` 贴图 + `ARMOR_ENTITY_GLINT_TEXTURING` + `VIEW_OFFSET_Z_LAYERING`。

26.3：该无参方法不存在；`RenderTypes.armorCutoutNoCullGlint(Identifier texture)` 需要盔甲贴图，
而本项目通用盔甲 SPI 只拿到调用方传入的 `RenderType`，拿不到贴图。
26.3 存在 `RenderTypes.trimmedArmorGlint()`，其 setup 与 26.2 `armorEntityGlint()` **逐项一致**：
`GLINT` pipeline、`ENCHANTED_GLINT_ARMOR`、`ARMOR_ENTITY_GLINT_TEXTURING`、`VIEW_OFFSET_Z_LAYERING`
（26.3 额外 `withForcedSolidModelPhase()`，用于正确的 solid 阶段提交）。

**结论：`RenderTypes.armorEntityGlint()` → `RenderTypes.trimmedArmorGlint()`，视觉/阶段语义不变，
不改变 `IArmorRendererBase` 等公共 SPI 的签名。** 需在文档中记录该映射。

### 2.5 `LivingEntity.swing` 签名变更（Mixin 运行时破坏）

- 26.2：`void swing(InteractionHand hand, boolean fromServerPlayer)`
- 26.3：`boolean swing(InteractionHand hand, SwingAnimation animation, boolean sendToSwingingEntity)`
  （`SwingAnimation` = `net.minecraft.world.item.component.SwingAnimation`，`SwingAnimation.DEFAULT`）

`LivingEntityMixin` 的 `@Inject` 目标描述符必须改为
`swing(Lnet/minecraft/world/InteractionHand;Lnet/minecraft/world/item/component/SwingAnimation;Z)Z`，
回调改为 `CallbackInfoReturnable<Boolean>`；`ISwingable.onEntitySwing` 返回 true 时
`cir.setReturnValue(false)` + `cir.cancel()`（26.3 `swing` 返回 false 表示未触发 swing，
与原 `void` 版本 cancel 的语义一致）。

### 2.6 其余 Mixin 目标（已逐一对照 26.3 源码，均未变）

| Mixin | 26.3 目标 | 结论 |

| `EntityMixin` | `Entity.spawnAtLocation(ServerLevel, ItemStack, float)` | 不变 |

| `LevelPropertiesMixin` | `PrimaryLevelData.worldGenSettingsLifecycle()` + 字段 | 不变 |
| `LivingEntityMixin` | `causeFallDamage(double, float, DamageSource)` | 不变 |
| `MinecraftServerMixin` | `<init>`、`stopServer` | 不变 |
| `ModelLoaderMixin` | `ModelBakery.<init>` | 不变 |

### 2.7 AccessWidener 条目（已对照 26.3 源码，均有效）

- `ItemTransform$Deserializer` / `ItemTransforms$Deserializer`：26.3 仍在
  `net/minecraft/client/resources/model/cuboid/`，构造器可访问。
- `NodeEvaluator.entityWidth/entityHeight/entityDepth`：26.3 仍为 `protected int` 字段。
- `ChunkMap.getVisibleChunkIfPresent(long)`：26.3 仍为 `protected` 方法。

**无需修改 `uranus.accesswidener`。**

### 2.8 元数据

- `uranus.mixins.json` 的 `compatibilityLevel`：`JAVA_17` → **`JAVA_25`**
  （26.3 官方/Architectury/Fabric 的 mixin 配置均使用 `JAVA_25`；26.2 遗留的 17 与 Java 25 字节码不匹配的风险必须消除）。
- `fabric.mod.json`：`minecraft` 从 `26.x` 收紧为 `>=26.3`；显式声明
  `fabricloader >=0.19.5`、`fabric-api >=0.160.5`、`architectury >=22.0.5`（architectury 以 nested jar 形式提供，
  但仍应声明依赖以保证生产环境被显式满足）。
- `neoforge` 模块：基线中即未加入 `settings.gradle`（26.2 阶段只构建 Fabric），本次移植目标为 Fabric，
  **不删除、不移动、不改写** NeoForge 实现；其元数据保持基线状态，待后续 26.3 NeoForge 移植阶段处理。
  这不影响 common/fabric 的 Architectury 抽象与未来多加载器能力。

### 6.3 环境/构建注意事项

1. **打包链路**：`fabric/build.gradle` 中 `configurations.shadowBundle.singleFile` 的惰性求值会丢掉
   `:common:transformProductionFabric` 任务依赖；已在 `jar {}` 中显式 `dependsOn project.configurations.shadowBundle`。
   没有该修复时，clean build 会失败或产出缺少 common 类的坏 jar（与 26.3 无关，是基线遗留构建缺陷，
   在本次移植的干净构建验收中暴露并修复）。
2. **NeoForge 模块**：按 AGENTS.md 要求保留 `neoforge/` 目录与源码，未删除/未移动；基线中它本就未加入
   `settings.gradle`（26.2 阶段只构建 Fabric），本次移植目标为 Fabric，故其 1.21.1 时代的构建脚本与元数据
   保持基线状态，待后续 NeoForge 26.3 移植阶段处理。common 的 Architectury 抽象层与未来多加载器能力未受影响。
3. **Gradle/JDK**：Gradle 9.5.1 + JDK 25；Architectury Loom 1.17.493 / Architectury Plugin 3.5.170
   与 architectury 26.3 官方一致。
